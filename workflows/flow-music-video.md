# Workflow: Music video & song visualizer

Aspect ratio and target platform come from `brief.md`. The container structure = the song structure: `Intro, Verse 1, Chorus 1, Verse 2, Chorus 2, Bridge, Outro` (adapt to the user's actual song; do not invent sections that do not exist).

## Rules

1. **The song is the source.** Ask for the lyrics / file / song structure in the brief (card 2 may be replaced with: song duration · which sections exist · whether there is a performer/character · target tool). The visuals are mapped to the lyrics & the energy of each section, not the other way around.
2. **Lyric mapping:** each section gets one mapping line in `konsep.md`: lyric image → visual scene → bible character/location used. The same image in a repeated chorus uses the **same scene/location** (repetition is MV structure, not a mistake).
3. **Chorus escalation:** the most dynamic camera movement & lighting contrast are saved for the Chorus & Bridge; Verses are more static/atmospheric. Record an energy level per section (1–3) in the script so the video prompts stay consistent.
4. **Dialogue:** MVs generally have no dialogue — the LANGUAGE block uses the `NO spoken dialogue` form, unless the user explicitly asks for a dialogue scene. Singing/lip-sync of the song: state in LANGUAGE the exact song line being sung, or prohibit lip-sync if the performer does not sing on camera (a brief decision).
5. **Loop & dissolve:** if the MV is meant to loop (Shorts/Reels), the first and last shots are designed to join by dissolve: the subject's position & the light direction are recorded in the final scene's CONTINUITY.
6. **Audio:** for an MV, gate 7 contains the section→song-timecode mapping and edit cues, not a new OST — the song already exists. An OST/Suno prompt is made only if the user does not yet have a song and asks for one to be written.
